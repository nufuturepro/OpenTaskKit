# Design

## Context

See proposal.md for the motivation. The current state that shapes the approach:

- The Actions menu is data (`bulkMenuGroups` in `web/src/app/bulk/BulkActions.tsx`) rendered by the shared `ActionMenu` (`web/src/app/menus/ActionMenu.tsx`) over the design-system `Menu`/`Popover` (`web/src/ui/overlay/Menu.tsx`, `Popover.tsx`). Picker items swap the items for a `ComboboxPanel` inside the same overlay; confirm items close the menu and open a dialog; `NoClose` wraps an item whose picker must not close the menu.
- The date picker is `dating` state inside `BulkActionsMenu` rendering a modal `Dialog` with a `DateField`. Its hosts render the menu **conditionally**: `{ctxMenu && …}` and `{actionsOpen && ticked === 0 && …}` in `TaskListView.tsx` and `useBulkList.tsx`. Clicking "Pick a date…" sets `dating` and closes the menu in the same tick; the host then unmounts the whole component, so the dialog never renders. The same race destroys `review` (Move/Assign) from a right-click. The Selection bar renders the menu unconditionally while `ids.length > 0`, which is why those paths work — the bug is host-shaped, not menu-shaped.
- `ActionGroup` items are full-width rows (`MenuItem` in `web/src/ui/Menu.tsx`); the Priority group is four of them (`label: t('Priority {p}')`, `shortcut: String(p)`).
- Overlays mount with `opacity: pos ? 1 : 0` in `Popover.tsx` (position, then show) and `Dialog` has `animation: none` from 640 px. `index.css` already defines `--duration-ui: 120ms`, `--ease-calm`, `dialog-sheet-up` for the phone sheet, `:root[data-motion="none"]` (zeroes every duration and animation — display mode's hook) and a global `prefers-reduced-motion` rule that makes animations instant and leaves only colour/opacity transitions.
- Appearance prefs are additive `user_prefs` strings (`theme_mode`, `theme_accent`, `density`, `row_detail`) read by `readAppearance`, written by `setAppearance` through the op log, applied by `applyAppearance` as root attributes; `AppearanceProvider` re-applies on every row change. Display mode's `useRootPresentation` sets and then **removes** `data-motion`, which would erase a user preference set on the root.
- Open changes touching the same specs: `motion-v2` ADDs web-app "Overlay motion" (dialogs, toasts, the task panel, the completion moment — explicitly *not* menus: "menus and popovers keep the 120 ms fade"), MODIFIES design-system "Reduced motion" and ADDs a `user_prefs.haptics` requirement to appearance-preferences; `calm-rows`/`rows-v2` touch "Appearance in Settings". This change MODIFIES only action-menus "Every action menu uses the shared menu behaviour" (row layout) and otherwise ADDS requirements (D7).

## Goals / Non-Goals

**Goals:**
- Every dialog a menu opens actually opens, from every host, including after a right-click.
- The calendar appears attached to the menu, in one overlay, with a keyboard order that steps back before it closes.
- The menu fits a 1080p screen without scrolling once Priority is one row.
- One entrance animation language for all overlays, 120 ms, with an account-level off switch and no regression for reduced-motion users.

**Non-Goals:**
- Exit animations: menus unmount at once (the chosen action's effect must be visible immediately — `motion-v2` D5 agrees).
- Completion, reflow, haptic, toast or task-panel motion (`motion-v2`).
- A per-device motion override; appearance preferences are synced by spec ("Appearance is personal, synced and offline").
- Compacting the date quick-picks or other menu groups; hover fly-out submenus; drag-to-resize panels.

## Decisions

**D1. The hosts keep the menu mounted until it reports all closed.** `BulkActionsMenu` gains an optional `onAllClosed` callback, called from an effect when `open === false && !dating && !review && !confirm` (and again whenever that becomes true). The right-click and `.`-cursor hosts split their state: the entry (`{ids, x, y}` or the cursor id) is cleared by `onAllClosed`, while `onOpenChange(false)` only flips an `open` flag — so the component that owns `dating`/`review` stays alive until the dialogs it opened are gone. The Selection bar already mounts unconditionally and passes no callback. Alternative: lift `dating`/`review` into each host. Rejected: four hosts would each reimplement the dialog wiring, and the next dialog (a future confirm) would silently break again — the menu should own its dialogs' lifetime. The callback is named for what it means: *nothing this menu opened is still on screen*.

**D2. The date picker is a panel item, rendered beside the items in the same overlay.** A new `ActionItem` kind, `kind: 'panel'` with `panel: PanelSpec { title, render(close) }`, wrapped in `NoClose` like pickers. `ActionMenu` holds `panel` state; while set, the menu content becomes a flex row: the ordinary items column (unchanged width class) plus a `w-72` column with a header ("Date", a back button) and the panel's content. The `Popover` already re-places itself on `ResizeObserver`, so the panel grows the overlay toward the side that has room, and `place()` clamps it to the viewport. Escape is intercepted exactly like a picker step: first Escape clears `panel` (focus returns to the item that opened it), second closes the menu — the existing `onOpenChange` guard in `ActionMenu` gains `|| panel`. Below 640 px `useWide()` is false: the sheet renders the panel *instead* of the items (the picker-step pattern, with the same back header), because a two-column sheet is unusable on a phone. The panel is the only consumer-facing new kind; pickers and steps keep their swap behaviour (a searchable list wants the whole width; a calendar wants to sit beside its menu). Alternative: a second `Popover` anchored to the first. Rejected: two overlays fight over Escape, focus and outside-tap in the overlay stack, and it *is* the detached popup the request replaces. Alternative: keep the modal `Dialog` and only fix the unmount. Rejected: the request is explicitly "alongside the menu, not as a popup".

**D3. The panel content is a phrase input plus the inline `CalendarGrid`, not `DateField`.** `DateField` embeds its own popover calendar (a popup inside a popup). The panel reuses `parseDateInput`, `CalendarGrid` and the same error string from `web/src/app/datetime/`, committing the typed phrase on Enter/blur and picking on a grid click; one pick calls `runBulk(ids, {kind: 'due', pick: iso})` and closes everything (the toast carries Undo, as the quick-picks do). Focus moves into the panel's input when it opens and returns to the "Pick a date…" item on Escape-back (the item keeps a ref through the open cycle).

**D4. Priority becomes one row through the group, not a special case in the menu.** `ActionGroup` gains `layout?: 'row'`; `Items` renders a row group's items inside a `flex` strip instead of stacked. `MenuItem` gains `compact?: boolean`: no icon column, the label centred as a square button, `checked` shown as the accent fill rather than a check icon. `bulkMenuGroups` maps `[1,2,3,4]` to `label: String(p)` + `compact` + `checked: sharedPriority === p` where `sharedPriority` is the priority every targeted task has (null when mixed, so nothing shows checked). The **accessible name stays "Priority {p}"**: the visible digit is the button's text, the full name is carried by `aria-label`, which contains the visible digit (WCAG 2.5.3 holds: "Priority 1" ⊇ "1"); `data-menu-label` stays "Priority {p}" so type-ahead is unchanged, and the roving model sees four ordinary `menuitem`s. The per-item `shortcut: String(p)` badge goes — the digit *is* the label now — but `aria-keyshortcuts` stays on the item so assistive tech still hears "1". Alternative: `role="radiogroup"` with radios. Rejected: the menu keyboard model queries `[role^="menuitem"]`, type-ahead reads `data-menu-label`, and one group's semantics would need a second navigation path for four buttons — not worth it for a mutually exclusive set the checked state already conveys. The spec's "no row of side-by-side buttons" is relaxed precisely and only for this (D7).

**D5. One entrance animation, one existing off switch.** `index.css` defines `@keyframes overlay-in` (opacity 0→1, translateY −4 px→0, scale 0.98→1) over `--duration-ui` with `--ease-calm`, applied to the `Popover` panel (only once `pos` is set, so it never animates from 0,0) and to the `Dialog` card from 640 px; the phone sheet keeps `dialog-sheet-up`. No exit animation (menus unmount; dialogs close through the same instant path as today). The existing `prefers-reduced-motion` rule already runs animations instantly, and `:root[data-motion="none"]` already zeroes them — so the preference is *just* an attribute. New additive `user_prefs.motion` (`''` | `none`, default `''` = on): one `kString` line in `internal/sync/ops.go`, `motion: ''` in `types.ts`/`USER_PREFS_DEFAULTS`, `motion` on `Appearance` read as `row?.motion === 'none' ? 'none' : 'full'`, written through `setAppearance('motion', …)`, applied by `applyAppearance` (`data-motion="none"` set or removed). **Display coordination:** `useRootPresentation` stops calling `removeAttribute` directly and instead calls a tiny exported `syncRootMotion()` from `lib/appearance.ts` that re-applies the last-applied preference (module-level cache set by `applyAppearance`, default "no attribute"), so leaving display mode restores the user's choice instead of erasing it; `lib/appearance.ts` stays free of display imports (display imports it, not the reverse). Alternative: a second attribute for the user pref. Rejected: two selectors over the same block, and every future no-motion rule would need them both. The display route's own `motion: 'none'` option keeps setting the same attribute while it is open.

**D6. Interface budget and copy.** No new chrome, row, scroll region or shortcut: the menu gets three rows shorter, the panel replaces a modal (no new region above any list), the switch is one `SettingRow` on a page that has them, and no shortcut is registered. Copy: the row is "Motion" with the sentence "Menus and dialogs glide in when they open; off makes everything appear at once." (new strings in `settingsCopy.ts`, indexed in `settingsIndex.ts`, translated into all six catalogs). The priority buttons reuse `Priority {p}`; the panel reuses `Date`, `Back`, `Not a valid date…` and `Pick a date`.

**D7. Spec placement.** action-menus "Every action menu uses the shared menu behaviour" is MODIFIED (its "no … row of side-by-side buttons" must change; no open change touches it). action-menus **ADDs** "Date picker alongside the menu" (the panel, its Escape order, its narrow fallback, the one-overlay rule) and "A dialog opened from a menu outlives the menu" (the host contract, with the right-click review scenario — the bug's regression spec). appearance-preferences **ADDs** "Motion preference" (rather than editing "Appearance in Settings", which `calm-rows` modifies; when it archives, a follow-up line adds the switch to that requirement's list). web-app **ADDs** "Entrance motion" — a different requirement name than `motion-v2`'s planned "Overlay motion", and its design.md is annotated (D8) so the two do not grow overlapping timing rules.

**D8. Coordination with `motion-v2`.** `motion-v2/design.md` D5 already specifies that menus and popovers fade in over `--duration-ui` and unmount at once, and that the preference for them is out of its scope; this change *delivers* that half now with the same tokens, and its D5 is annotated to say the menu/popover/dialog entrance shipped here (its remaining work: dialogs' emphasis-duration exit, the sheet's exit, the task panel, toasts). Its spec delta for web-app "Overlay motion" is edited at archive time to drop what "Entrance motion" already states. Its haptics requirement and this motion requirement are different names in the same capability and compose cleanly.

**D9. Offline and sync.** All of it is presentation plus one preference: the panel, the compact row and the animation read no server state; `motion` rides the existing op log (additive, last-writer-wins per field, in the export/import like `density`), older clients store and forward it unknown, and the server binary changes only by that schema line. Bundle: no dependency; ~1 KB CSS, <0.5 KB JS.

## Risks / Trade-offs

- [Two-column overlay wider than the viewport] → `place()` already clamps `left`/`maxWidth` to the viewport, and below 640 px (or when narrow) the sheet shows the panel alone; the panel column is fixed `w-72`, the items column keeps its class.
- [Focus lost when the panel closes] → focus is restored to the item that opened it; the first Escape never closes the menu while a panel is open (same contract as picker steps, already tested).
- [The `onAllClosed` effect firing before a dialog's state lands] → both `dating`/`review` set and menu close happen in one React batch, so the effect observes the settled pair; a regression test opens pick-a-date and move-review through the right-click host.
- [A user turns motion off while display mode is active] → display owns the attribute while open; on leave, `syncRootMotion()` applies the cached preference.
- [Row layout creeping to other groups] → `layout: 'row'` exists for groups of mutually exclusive single-purpose choices; the spec sentence names that constraint; other groups stay rows-of-items.
- [The compact row hurting type-ahead] → `data-menu-label` is unchanged, so "pri" still lands on Priority 1.

## Migration Plan

No data migration: `user_prefs.motion` is an additive field read with a default. Ships with the next build; older clients keep and forward it (op-schema rule). Rollback is reverting the commit: the stored `none` then reads as "on" for older clients and changes nothing.

## Open Questions

- Whether the panel's phrase input should also offer the quick-pick words as chips (Today/Tomorrow) inside the panel. Deferred: the menu rows above it already do that job, and adding chips doubles the panel's height.
- Exact checked-state styling of the compact row (accent fill vs ring) is tuned in the component, not spec'd.
